## Примечание: диагностика Executions важна (24.10.2026)

После просмотра настроек пользователь отметил, что полное отключение истории лишит нас возможности нормально исследовать ноды при сбоях. Это верно: n8n позволяет отдельно сохранять успешные, ошибочные и ручные execution; сохранённые данные служат материалом для Debug. Поэтому инструкция выше «отключить всё немедленно» **пересматривается, не считать согласованной**.

**Временное предложение для закрытых тестов строго на искусственном Markdown без секретов:** `Save` для failed/successful/manual, `Do not save` для progress; заранее выбрать короткую политику очистки и после теста проверить удаление записей. До исправления retention и разрешения тестов ничего не запускать. **Для эксплуатации:** KB-путь должен писать только безопасные метаданные ошибок, не исходный Markdown/binary, а хранение менеджерских execution настраивать отдельно. Если всё остаётся одним Workflow, настройки применяются ко всему Workflow, поэтому разделение KB и менеджерских путей требует проектного решения. Никакие изменения UI не производились ассистентом.
