# DASH-02 — экран, визуализация и фильтры

**Цель дизайна:** первое чтение за 15–30 секунд. Один основной экран, без «стены из графиков».

## Предлагаемый макет v1 (desktop)

```text
Катона / Обзор                                  Обновлено: <время>
[ 7 дней | 30 дней | период ]     [ Канал ▼ — если >1 ]

[ Новые обращения ] [ Достигли цели ] [ Конверсия ] [ Потеряны ]

[ ГРАФИК: новые обращения по дням       ] [ ВОРОНКА или СТАТУСЫ ]
[ 1 серия; 2-я только при наличии данных] [ компактные полосы   ]

Требуют внимания менеджера: <N>   (только при подтверждении источника)

Последние обращения                       [ Статус ▼ — только таблица ]
Дата/время | Канал | Этап | Статус | Цель | Менеджер?
строки (10–20), безопасные сведения, постраничная навигация
```

На телефоне: KPI по 2 в ряд, графики друг под другом, таблица как компактные строки/карточки; горизонтальная прокрутка страницы нежелательна.

## KPI

- Только **четыре** верхние карточки: обращения, достигли цели, конверсия, потеряны.
- Без финансовых KPI, затрат OpenAI и «себестоимости диалога» (пользователь явно исключил их).
- В одной карточке одно крупное значение и короткое пояснение; сравнение с предыдущим периодом **не добавлять** в v1 без проверенного контракта.
- Для недоступной метрики: «—» и подсказка «источник пока не подтверждён»; для пустого периода «0 обращений», конверсия «—». Для ошибок — отдельное ненавязчивое сообщение с повторной загрузкой.

## Графики

1. **Динамика**: столбцы по дням (при длинном периоде допустима агрегация по неделям с подписью), ноль отображать как ноль, tooltip показывает точную дату и число. Две серии только если «достигли цели» достоверно привязаны к исходной дневной когорте.
2. **Воронка**: горизонтальные последовательные полосы с числами и долей от начальных обращений, **только если** история этапов позволяет строго установить «достигал этапа». При отсутствии такого источника использовать **«Распределение по текущим статусам/этапам»** — НЕ называть его воронкой и не обещать конверсию между ступенями. Максимум 5–6 пунктов, длинные хвосты группировать «Прочие» с расшифровкой.
3. Без круговой диаграммы для каждого статуса, декоративных 3D-эффектов, постоянно анимированных графиков и десятков карточек.

## Фильтрация

| Фильтр | Где | Поведение |
|---|---|---|
| Период | Вся аналитика, главные KPI, графики и таблица | Быстрые 7/30 дней, произвольные даты; по умолчанию последние 7 дней, timezone Europe/Moscow |
| Канал | Вся аналитика, если 2+ фактически подключённых канала | `Все / Telegram / другие реальные`; при единственном Telegram не показывать пустой переключатель |
| Статус | Только таблица диалогов | Не изменяет незаметно знаменатель KPI/конверсии |
| Менеджер | Позже, когда есть подтверждённая история назначения | Не показывать фильтр, который не работает |
| Поиск | Не входит в v1 | Не вводить поиск по телефону/имени без политики доступа к ПД |

Изменение периода/канала приводит к согласованному обновлению всех элементов, кроме независимого оперативного индикатора менеджера с подписью «сейчас». Фильтры отражаются в URL по возможности, без PII; возврат/обновление страницы не сбрасывает выбор неожиданно. Даты `from`/`to` обрабатываются по единым границам.

## Таблица обращений

- По умолчанию 10 последних, максимум 20 на страницу. Сортировка по последнему событию, затем стабильный tie-break по ID; cursor или страница, как позволит SQL.
- Колонки: дата/время, канал, этап, статус, целевой результат, менеджер (только после подтверждения атрибуции).
- Никаких телефонов, персональных ID Telegram, сырых сообщений или имён без отдельного режима разрешений.
- Клик в карточку обращения — **вынести во v2** после обсуждения прав доступа; не делаем псевдоссылок без функциональности.

## Обязательные состояния

Загрузка: skeleton, без выдуманных чисел. Нет данных: полезный пустой экран. Ошибка Supabase/API: понятное сообщение, кнопка «Повторить». Метрика недоступна: явно показывать частичность отчёта. Актуальность: короткая метка «Обновлено в ...». Поддержка клавиатуры, контраст, осмысленные подписи, легенда с 2–3 терминами максимум, русская локаль.

## Критерии UX-приёмки

- Руководитель видит главные KPI без прокрутки на обычном desktop-экране.
- Фильтры понятны, цифры между карточками и графиками не противоречат.
- У каждого процента есть определённый знаменатель; «потерянные» не подменяются «не отвечают».
- Нет перегрузки: 4 KPI + 2 визуализации + 1 таблица; дополнительные детали — не на первом экране.
- На мобильном устройстве читаемость и управление сохраняются.
