# DASH-04 — первый промпт VSCode и протокол работы

## Принцип передачи

ChatGPT — руководитель и контролёр проекта, пользователь передаёт **одну** задачу за раз в VSCode и возвращает его текстовый отчёт. VSCode не получает разрешение делать следующий этап самостоятельно. Передать следующий промпт только после анализа предыдущего отчёта.

## Первый промпт: DASH-D0-01 — аудит источников Supabase, без кода

```text
Продолжаем проект «Катона»: https://github.com/qbitstudioai-ai/katona

Ты — исполнитель VSCode. ChatGPT — руководитель проекта.
Задача DASH-D0-01: подготовить read-only аудит источников данных для отдельного дашборда руководителя.

1. Прочитай:
   PLAN.md
   DB_AUDIT.md
   DB_WORKFLOW_CONTRACT.md
   docs/01_BOT_REQUIREMENTS.md
   docs/dashboard/README.md
   docs/dashboard/01_METRICS_AND_DATA.md
   docs/dashboard/02_UX_AND_FILTERS.md
   docs/dashboard/03_IMPLEMENTATION_PLAN.md

2. Инвентаризируй реальные источники данных метрик: 4 KPI (новые обращения, достигли цели, конверсия, потерянные), дневная динамика, история этапов или их текущие статусы, последние обращения, ожидающие менеджера. Для каждого укажи физический источник (таблица/VIEW/функция), столбцы, условия фильтрации, допустимые статусы и степень подтверждения. Особо изучи audit_dashboard_summary и роль katona_dashboard_read.

3. Если прямого read-only доступа к Supabase нет, НЕ пытайся подключаться произвольными Credentials и НЕ угадывай структуру. Подготовь небольшой, безопасный SELECT-only SQL для запуска пользователем в Supabase SQL Editor и точно обозначь, какие части ещё не подтверждены.

4. Отдельно проверь, что конверсия учитывает DISTINCT dialog_id и достижение цели, а не количество сообщений, что даты относятся к первому входящему событию, и можно ли восстановить историю этапов. Если нельзя, предложи достоверную альтернативу воронке.

5. Сохрани результат в docs/dashboard/DATA_AUDIT.md. Обнови только чек-лист D0 и ссылки в PLAN.md по фактам. Не меняй остальную документацию без необходимости.

Запреты: никаких CREATE, ALTER, GRANT, UPDATE, DELETE, миграций, запусков n8n, обработки персональных данных, импортов/экспортов Workflow. Не создавать frontend, backend, SQL-функции и таблицы. Не подключать VSCode/Codex к живому сервису с правами на запись. Не менять клиентский и служебный Workflow и не трогать базу знаний.

В конце отчитайся:
- какие файлы изменены и commit SHA (если коммит был);
- что реально подтверждено источниками, а что осталось гипотезой;
- таблица метрика → Supabase-источник → доступность;
- что нужно получить от пользователя (только если прямой аудит невозможен);
- выполненные проверки;
- готовность D0 и ровно один рекомендуемый следующий шаг.

Не переходи к D1 без нового задания от ChatGPT.
```

## Формат следующего сообщения пользователя ChatGPT

Передать отчёт VSCode целиком, особенно SQL-выводы/ошибки, список изменённых файлов и commit SHA. ChatGPT сравнит их с этими документами, при необходимости даст только один SELECT или уточняющий prompt. D1 разрешается **после** аудита, не по факту создания `DATA_AUDIT.md`.

## Работа с репозиторием

- Не добавлять временные SQL dump, реальные JSON Executions, CSV с ПД, скриншоты токенов, `node_modules`, build output и случайные файлы.
- Принцип «одна задача — один логический блок»; в каждом блоке отмечать итог и незавершённые пункты, не переписывать старую историю.
- Новые решения и архитектурные ограничения сначала фиксировать в `docs/dashboard/`, затем передавать реализации.
