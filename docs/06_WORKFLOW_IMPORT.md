# Импорт двух n8n Workflow Катоны — закрытый Telegram-тест

**Обновлено: 2026-10-22. Статус: ✅ актуальные обезличенные JSON сохранены в публичном GitHub; ⚠️ runtime-проверка импортированных рабочих версий не выполнена.**

Павел предоставил свежие экспорты из n8n (сообщено, что версии импортированы, однако входящий Telegram Webhook служебного бота пока не срабатывает):

- `workflows/current/Катона — Клиентский Telegram — CREDENTIALS FIXED (ТЕСТ).json` — 160 нод;
- `workflows/current/Катона — Служебный Telegram и база знаний — ЗАКРЫТЫЙ ТЕСТ.json` — 108 нод.

**GitHub содержит безопасные копии этих экспортов, а не побайтовые runtime-экспорты.** При публикации удалены n8n Credential references, идентификаторы Webhook, метаданные экземпляра, реальные Telegram ID служебной группы и тестировщика, а `active` установлен в `false`. Узлы и соединения сохранены. Для импорта из GitHub требуется заново указать Credentials и закрытые Telegram настройки в интерфейсе n8n; нельзя одновременно активировать дублирующие workflow.

На момент записи в репозитории `katona` устаревших JSON-файлов Qbit **не было**, поэтому удаление не требовалось. Исторические упоминания Qbit в документации описывают происхождение шаблона, а не текущие workflow.

## Подготовлено
- Все прямые SQL-ссылки переведены на схему `katona`.
- Telegram/PostgreSQL узлы используют по имени четыре уже созданных Credentials Катоны.
- Удалены старые внутренние credential ID от Qbit (внутренние ID новых Credentials неизвестны; n8n может потребовать привязать вручную после импорта).
- Указаны настройки компании Катона и четыре сценария: розница, подрядчик, тендер, сервис.
- Убраны старые ID сотрудников, профиль базы знаний Qbit, URL Qbit, STT Qbit.
- Клиентский список тестировщиков **пуст**, поэтому посторонние сообщения не передаются в ИИ/БД.
- Webhook пути изменены на `katona-test-...`. Вход сайта, Авито и MAX отключён.

## После импорта: делать строго до включения
1. ⬜ В n8n открыть оба Workflow и проверить выбор четырех новых Credentials: `Katona — Клиентский PostgreSQL`, `Katona — Служебный PostgreSQL`, `Katona — Клиентский Telegram`, `Katona — Служебный Telegram`.
2. ⬜ В узле `Настройки компании` добавить Telegram user_id только разрешённых тестировщиков в `testovye_telegram_user_id`. В узле `Настройки служебного бота` заполнить менеджеров, разрешённых отправителей документов и чаты.
3. ⬜ Настроить **собственный** OpenAI Credential (6+2 узла) и проверить модель `gpt-4.1-mini`. Для embeddings оставить `text-embedding-3-large`, 1024.
4. ⬜ Создать **новые** HTTP Header Auth Credentials для Telegram-входа и внутренних webhook (10+3 ранее использовали Qbit). Не снижать авторизацию.
5. ⬜ Заменить URL заглушки `SET_KATONA_N8N_HOST` на реальный адрес нужной установки n8n. URL `SET_KATONA_FORUM_BRIDGE_HOST` требует собственного безопасного способа вызова Telegram `createForumTopic`; старый Qbit Telegram-bridge не используется.
6. ⬜ Загрузить утверждённые документы Катоны, создать профиль индекса и указать новый ID в клиентском `rag.profil_indeksa_id`.
7. ⬜ Проверить Telegram webhook, отправку клиенту, захват/возврат оператором, права тем и отказ от рассылки на отдельных тестовых данных.
8. ⬜ Только после проверки запускать **закрытый** тест заказчиком. Покупатели не допускаются.

**Ограничения:** без утверждённого прайса — не озвучивать предварительные цены; без Битрикс24 — не сообщать о создании CRM-сделки или подтверждённой записи на замер.
