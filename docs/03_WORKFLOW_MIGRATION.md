# Катона — адаптация двух n8n Workflow
**Статус: 🔄 проектирование.** Активные Workflow и Credentials Qbit не менять.

## Клиентский Workflow (основа Qbit, 160 узлов)
1. Сохранить логику очередей, памяти, RAG, дедупликации, запретов повторной отправки и контроля передачи.
2. Все SQL-ссылки перевести на `katona`; использовать новый `Katona — Клиентский PostgreSQL`. Не использовать Qbit webhook, токены, Telegram-группы или адреса.
3. **Сохранить Telegram-вход** для пилота, но создать отдельного бота Катоны и новый webhook; по умолчанию принимать только Telegram user_id разрешённых тестировщиков. Публичные пользователи не должны проходить обработку.
4. Развести правила четырёх сценариев и избежать ненужного сбора контактов; отсутствие утверждённого прайса означает запрет на автоцены.
5. На этапе внутреннего Telegram-теста **не добавлять Битрикс24**; заявки и истории сохранять в `katona`, передавать менеджеру через собственную Telegram-группу. Не обещать регистрацию в CRM.
6. Заявка на замер означает передачу на согласование замерщику, а не самостоятельное бронирование.
7. Первое/второе напоминания: предлагаемые 3/24 часа, только после подтверждения условий и допустимости канала.
8. Подготовить JSON `active=false`, протестировать изоляцию от Qbit.

## Служебный Workflow (основа Qbit, 108 узлов)
1. SQL строго в `katona`, Credential `Katona — Служебный PostgreSQL`.
2. Сохранить разбиение Markdown, `text-embedding-3-large` с размером 1024, проверки качества и публикацию документов после тестов.
3. Использовать новую служебную Telegram-группу Катоны с темами для менеджеров и загрузки знаний; определить, создаём ли отдельного служебного бота (предпочтительно для изоляции от клиентского).
4. Адаптировать управление Telegram-темами из Qbit под **новую** группу и новых менеджеров Катоны; никогда не использовать идентификаторы и токены Qbit.
5. Все знания и векторы создать заново из утверждённых документов Катоны, не копировать Qbit.

## Уже готово
- Схема `katona`: 35 таблиц, 65 SQL-функций, 135 индексов, 5 триггеров, 69 FK.
- Два ограниченных Postgres-логина (30/28 разрешённых функций); два n8n Credentials созданы и по сообщению пользователя соединяются.
- На дату этого документа работа сайта, Битрикс24, загрузки знаний, продакшн-тесты **ещё не выполнены**.

**Порядок:** создать Telegram-бота и служебную группу Катоны → согласовать тестировщиков и отдельного служебного бота → адаптировать два JSON `active=false` → загрузить проверенные знания → закрытый тест заказчиком → сайт → Авито → Битрикс24.
