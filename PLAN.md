# Катона — план переноса бота Qbit

Обновлено: 2026-10-22. Репозиторий: `qbitstudioai-ai/katona`.

Статусы: ✅ готово · 🔄 в работе · ⬜ предстоит.

## Цель
Создать для Катоны два n8n Workflow, отдельную схему Supabase, затем дашборд. Исходные шаблоны Qbit — техническая основа; данные клиентов и знания Qbit не должны попадать в рабочую базу Катоны без отдельного решения.

## Что установлено по двум JSON
- Клиентский Workflow: 160 узлов; Telegram, AI guard/planner/answer, RAG, напоминания, передача менеджеру, сохранённые исходящие события и восстановление очередей.
- Служебный Workflow: 108 узлов; захват и возврат диалога, ручные ответы менеджера, загрузка Markdown, генерация фрагментов и векторов, проверка и публикация знаний.
- Оба Workflow ссылаются на исходную схему `qbit_bot_pervichnogo_obrascheniya`; вместе непосредственно вызывают 43 разные SQL-функции. Реальный набор таблиц/зависимостей устанавливается только запросами к Supabase.
- База знаний использует `text-embedding-3-large`, размерность 1024; поиск клиента требует актуального ID профиля индекса.
- Рабочий вход сейчас — Telegram. Сайт, Avito и MAX в клиентском JSON — заглушки.
- Есть прямые привязки к инфраструктуре Qbit: webhook URL, внутренний Telegram-bridge, имена Credentials, ID группы/менеджеров, адрес сервиса голоса и worker ID.

## Кто что делает
- **Руководитель (ChatGPT):** анализ, план, SQL, изменённые JSON, проверочные сценарии; обновляет статусы.
- **Пользователь:** запускает SQL в Supabase, импортирует JSON в n8n, настраивает Credentials, возвращает отчёты; затем модерирует VS Code.

## Правила переноса
1. **Не запускать** создание/копирование, пока не получена инвентаризация базы и резервная копия.
2. `CREATE TABLE ... LIKE INCLUDING ALL` не заменяет полноценную миграцию: не переносит функции, внешние ключи, триггеры и RLS-политики.
3. При отдельном Supabase-проекте обычный SQL Editor исходного проекта не может напрямую копировать данные в другой проект: потребуется экспорт и импорт.
4. Не переносить историю и персональные данные Qbit в Катону по умолчанию.
5. Исходные JSON содержат настройки инфраструктуры; не публиковать их в открытом репозитории без очистки секретов и идентификаторов.
